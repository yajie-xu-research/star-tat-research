# Data Dictionary — STAR-TAT (P1)

Five tables, one CSV per table, column contracts in `schemas/`. All
timestamps are ISO-8601 UTC. All records are synthetic case records for
method demonstration and reproducibility, generated by a seeded,
deterministic generator.

## cases.csv

| Column | Type | Meaning |
|---|---|---|
| case_key | string | Unique case identifier (`CASE_00000001`) |
| site_key | string | `SITE_A` / `SITE_B` / `SITE_C` |
| workflow_version | string | `WF_V1` / `WF_V2` / `WF_V3` (validity windows in the stage dictionary) |
| test_family | string | Test family (`ONCO_PANEL` / `GERMLINE` / `RARE_DISEASE` / `PHARMA`) |
| priority_class | string | `ROUTINE` / `STAT` |
| received_at_utc | timestamp | Case receipt time |
| released_at_utc | timestamp | Release time; empty when `is_completed` is 0 |
| is_completed | 0/1 | 1 when the case has a release timestamp |

Primary key: `case_key`. Invariant: `released_at_utc > received_at_utc`
when completed.

## events.csv

| Column | Type | Meaning |
|---|---|---|
| case_key | string | Parent case |
| event_code_raw | string | Raw site vocabulary code (see stage dictionary) |
| occurred_at_utc | timestamp | When the event happened |
| known_at_utc | timestamp | When the system learned of the event (`>= occurred_at_utc`) |

Primary key: `(case_key, event_code_raw, occurred_at_utc)` (approximated
as a full-row key). Late-known events (`known_at_utc` after a request's
`as_of_utc`) are invisible to that request.

## load_snapshots.csv

| Column | Type | Meaning |
|---|---|---|
| site_key | string | Site the instruments belong to |
| workflow_version | string | Version the snapshot belongs to |
| snapshot_at_utc | timestamp | Observation time |
| queue_size | int >= 0 | Cases queued at the site |
| batch_load | float >= 0 | Instrument batch occupancy |
| instrument_util | float in [0, 1] | Instrument utilization fraction |
| source_system | string | System that emitted the snapshot row |
| record_version | int | Snapshot row version |

Only the latest snapshot at or before `as_of_utc` is visible to a request.

## stage_map.csv

| Column | Type | Meaning |
|---|---|---|
| site_key | string | Site vocabulary owner |
| workflow_version | string | Version the mapping belongs to |
| event_code_raw | string | Raw event code |
| canonical_stage | string | One of the seven frozen canonical stages |
| valid_from | date | Window start (version validity) |
| valid_to | date | Window end |
| reviewed_by | string | Dictionary review role id (fictional) |

SITE_C's local chain has no `SEQUENCING_STARTED` row (the sequencing step
runs offsite), so SITE_C predictions use its six-stage chain. The
dictionary declares the SITE_C/`SEQUENCING_STARTED` combination
NOT_COMPARABLE; the method never fabricates a sequencing event.

## predict_requests.csv

| Column | Type | Meaning |
|---|---|---|
| request_id | string | Unique request identifier |
| case_key | string | Target case |
| as_of_utc | timestamp | The only time the prediction may use |
| purpose | string | `OPERATIONAL_ETA` / `PILOT_CHECK` / `RETRO_AUDIT` |

Primary key: `request_id`.

## Frozen canonical stages

`SAMPLE_RECEIVED`, `ACCESSIONED`, `LIBRARY_PREPARED`,
`SEQUENCING_STARTED`, `ANALYSIS_COMPLETE`, `REVIEWED`, `RELEASED`.

## Rejection reasons (ABSTAIN)

| Reason | Trigger |
|---|---|
| `UNKNOWN_WORKFLOW_VERSION` | Version not in the stage dictionary |
| `FEATURE_UNAVAILABLE` | No load snapshot visible at `as_of_utc` |
| `UNMAPPED_STAGE` | Visible event prefix contains an unmapped code |
| `INSUFFICIENT_CALIBRATION` | Stratum has too few calibration rows |
| `SHIFT_DETECTED` | Load features outside trained Tukey-fence ranges |

## Exclusion reasons (audit ledger `excluded_rows.csv`)

| Reason | Level | Trigger |
|---|---|---|
| `LATE_KNOWN_EVENT` | event | Event known only after the request time; excluded from that request's snapshot |
| `CENSORED` | request | Case never completed; target kept unset |

Other defined exclusion codes (`FUTURE_LOAD_SNAPSHOT`,
`AS_OF_AFTER_RELEASE`, `NO_TARGET`, `MISSING_CASE`) are implemented in the
snapshot and target paths but produced zero rows in the shipped run; the
generated data does not trigger them.
