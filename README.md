# star-tat-research

Stage-normalized turnaround-time (TAT) interval prediction for multisite
laboratory workflows, built as a reproducible research codebase.

The repository carries synthetic case records for method demonstration and
reproducibility, generated by a seeded, deterministic generator. Every
prediction is as-of honest: features are derived
only from information the system could have known at the request's
`as_of_utc`, and outcomes live in a physically separate ground-truth
directory that feature code cannot read.

## What it does

- Normalizes raw per-site event streams into a frozen seven-stage canonical
  chain (sample receipt through release).
- Rebuilds an as-of snapshot per prediction request (stage reached, elapsed
  time, current instrument load) from events and load snapshots known at
  `as_of_utc`.
- Fits a per-stratum (site x workflow version) gradient-boosting point model
  on the training block, then turns it into a prediction interval with a
  calibration-block absolute-residual quantile (coverage target is a
  program parameter), with a split-conformal comparison.
- Reports five baselines side by side: historical median, stage/version
  stratified empirical quantiles, raw-timestamp linear point prediction,
  tree point prediction, and an unstratified interval method.
- Rejects requests it cannot answer honestly: `UNKNOWN_WORKFLOW_VERSION`,
  `FEATURE_UNAVAILABLE`, `UNMAPPED_STAGE`, `INSUFFICIENT_CALIBRATION`,
  `SHIFT_DETECTED`.

## Layout

```
configs/            p1_stages.yaml (frozen stage dictionary), p1_policy.yaml
schemas/            JSON column contracts for the five data tables
src/star_tat/       common (hashing, isolation, manifest, run ids) + p1 package
tests/              114 pytest cases
synthetic_data/     seeded generator output (seed 20240115), git-tracked
outputs/runs/       curated historical runs (data/_ground_truth/ separated)
docs/               METHOD_CARD, DATA_DICTIONARY, USAGE_GUIDE,
                    frozen_metrics, pilot usage log (weeks 1-5)
research/decisions/ D01..D12 decision records
external/           external validation protocol (status NOT_OBTAINED)
environment.json    dual environment snapshot
CHANGELOG.md        release notes
```

## Quick start

```bash
uv venv venv --python 3.12
uv pip install --python venv/bin/python3 -e .
venv/bin/star-tat generate-synthetic --output synthetic_data --seed 20240115
venv/bin/star-tat validate --input synthetic_data --config configs/p1_stages.yaml
venv/bin/star-tat p1 replay --input synthetic_data \
  --as-of-file synthetic_data/predict_requests.csv \
  --out outputs/runs/p1_replay --seed 20240115
venv/bin/star-tat p1 evaluate --run outputs/runs/p1_replay \
  --out outputs/runs/p1_evaluation
venv/bin/star-tat manifest inspect --run outputs/runs/p1_replay
```

Run the suite with `venv/bin/python3 -m pytest`.

## Data scope note

All case identifiers, event timestamps, and load figures in `synthetic_data/`
are synthetic case records for method demonstration and reproducibility,
generated by a seeded, deterministic generator; the pipeline itself
does not care where a table came from as long as it satisfies the schemas in
`schemas/`.

## Governance

- Every run writes a `manifest.json` (run id, config/data/result hashes,
  status `INTERNAL_RESEARCH` for all historical runs in this repository).
- Ground truth (`data/_ground_truth/true_outcomes.csv`) is written by replay
  and read only by evaluation; feature and prediction code paths refuse to
  open that directory (see `src/star_tat/common/isolation.py`).
- Wall-clock fields never enter result hashes, so a re-run on the same
  inputs and config reproduces the same run id and result hash.
